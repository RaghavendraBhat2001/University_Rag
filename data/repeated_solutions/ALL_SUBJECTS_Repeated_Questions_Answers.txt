QUESTION #1  (6 Marks)  -  asked in 3 exam sittings [2023, 2022, 2021]
Question: Define Big oh notation. What is rate of growth, worst, best an average case complexity of an algorithm ?
----------------------------------------------------------------------
Model Answer:
BIG O NOTATION

📘 As per your notes, Big Oh notation is a mathematical notation used to describe the upper bound of the time complexity or space complexity of an algorithm as a function of the size of the input. It helps simplify the analysis of algorithms by ignoring details that do not impact the comparison of algorithms.

The rate of growth refers to how quickly an algorithm's running time or space requirement grows as the size of the input increases.

The worst-case complexity is the maximum time or space complexity that an algorithm can take, regardless of the specific input. For example, a linear search algorithm has a worst-case complexity of O(n) because it needs to check every element in the list.

The best-case complexity is the minimum time or space complexity that an algorithm can take, given the best possible input. For example, a binary search algorithm has a best-case complexity of O(log n) because it can find the target element in the middle of the sorted array in the best case.

The average-case complexity is the expected time or space complexity over all possible inputs. However, it can be difficult to calculate and is often not as useful as worst-case analysis for comparing algorithms.

💡 Simple way to understand it: Think of Big Oh notation as a highway speed limit sign. Just like how the speed limit tells you the maximum speed you can travel on a road, Big Oh notation tells you the maximum running time or space requirement an algorithm can have, regardless of the specific input. The rate of growth is like the type of car you're driving - some cars (algorithms) can travel faster (have better complexity) than others. The worst-case complexity is like driving in heavy traffic - it's the worst-case scenario where the algorithm takes the longest time. The best-case complexity is like driving with no traffic - it's the best-case scenario where the algorithm takes the shortest time. The average-case complexity is like driving on an average day - it's the expected time over all possible scenarios.

Question: Write an algorithm to sort the numbers using selection sort. Sort the numbers {1, 0, 6, 5, 4, 9, 2, 3} using your algorithm.
----------------------------------------------------------------------
Model Answer:
SELECTION SORT

 // C: Selection Sort algorithm to sort an array of integers

1. Initialize a function SelectionSort(int A[], int n) that takes an array and its length as input.
2. For each index i from 0 to n-1, do the following:
    a. Find the minimum value in the unsorted portion of the array (from index i to the end of the array).
    b. Swap the minimum value with the current index i's value in the array.
3. Return the sorted array.

SelectionSort(int A[], int n) {
    for (int i = 0; i < n - 1; i++) {
        int minIndex = i;
        for (int j = i + 1; j < n; j++) {
            if (A[j] < A[minIndex]) {
                minIndex = j;
            }
        }
        int temp = A[minIndex];
        A[minIndex] = A[i];
        A[i] = temp;
    }
    return A;
}

// Trace for the given array {1, 0, 6, 5, 4, 9, 2, 3}

Iteration | Min Index | Swapped Elements | Sorted Array
0 | 0 | 1, 0 | 0, 1
1 | 3 | 0, 3 | 0, 1, 3
2 | 5 | 3, 5 | 0, 1, 3, 5
3 | 6 | 5, 6 | 0, 1, 3, 5, 6
4 | 2 | 6, 2 | 0, 1, 2, 3, 5, 6
5 | 4 | 2, 4 | 0, 1, 2, 3, 4, 6

The sorted array is {0, 1, 2, 3, 4, 6, 5, 7}.

#define MAX 10000
long fib[MAX];

void fib_dp(int n) {
    int i;
    fib[0] = 0;
    fib[1] = 1;
    for (i=2; i<=n; i++) {
        fib[i] = fib[i-1] + fib[i-2];

}

long fib_dp_get(int n) {
    return fib[n];
}

Question: Write an algorithm to find square root of a number.
----------------------------------------------------------------------
Model Answer:
SQUARE ROOT ALGORITHM

 // C: Square root computation

#include <stdio.h>

double sqrt(double n, double eps) {
    double l = 1.0, r = n;
    double m;

    while (r - l > eps) {
        m = (l + r) / 2.0;
        if (m * m < n)
            l = m;
        else
            r = m;
    }

    return l;
}

int main() {
    double n, eps = 0.00001;
    printf("Enter a number: ");
    scanf("%lf", &n);
    printf("The square root of %.2lf is %.2lf\n", n, sqrt(n, eps));
    return 0;
}

This code implements the binary search algorithm for finding the square root of a number with a given precision. The user inputs a number, and the program outputs its square root with the specified precision.

Question: Write an efficient algorithm to find aⁿ where n is a large number.
----------------------------------------------------------------------
Model Answer:
ALGORITHM

📘 As per your notes, an Efficient Algorithm for fast exponentiation is described. This algorithm is used to compute the value of a^b for large values of a and b, which is useful in primality testing for cryptography.

The algorithm is a divide-and-conquer approach, meaning it breaks down the problem into smaller sub-problems, solves them, and combines the solutions to solve the original problem.

The algorithm works by using the following identity: ab = e * p(ln(ab)), where e is the multiplication of the last bits of a and b, p is a recursive function that computes a^(b/2) and a^(b/2) for the first half of the bits of a and b, and ln(ab) is the natural logarithm of ab.

The key advantage of this algorithm is that it reduces the problem of computing a^b to one multiplication and two recursive calls, making it more efficient for large values of a and b.

💡 Simple way to understand it: Think of the algorithm as a multi-level assembly line. Each worker (function) performs a specific task (multiplication or recursive call) on parts (a and b) to assemble the final product (a^b). The algorithm breaks down the assembly line into smaller sections (divide-and-conquer), making it more efficient to produce the final product for large orders (large values of a and b).

Question: Consider the following sentences. a) John likes all kinds of food. b) Apples are food. c) Chicken is food. d) Anything anyone eats and is not killed by food. e) Bill eats peanuts and is still alive. f) Sue eats everything Bill eats. Translate these sentences in to formulas in predicate logic. Prove that “John likes peanuts” using background chaining. Convert the formula into clause form.
----------------------------------------------------------------------
Model Answer:
PREDICATE LOGIC

📘 Predicate Logic:
Predicate logic is an extension of propositional logic that allows for the representation of statements about objects and properties of those objects. It introduces predicates, which are functions that associate objects with truth values, and quantifiers, which are used to express generalizations about all or some objects.

In predicate logic, formulas are built using predicates, variables, logical connectives, and quantifiers. Predicates are symbols that represent properties or relations, such as "is tall" or "loves". Variables represent specific objects or values, such as "x" or "y". Logical connectives, like "and", "or", and "not", are used to combine formulas. Quantifiers, such as "forall" (for all) and "exists" (there exists), are used to express statements about all objects or some objects.

💡 Simple way to understand it:
Think of predicate logic as a more complex version of propositional logic. Instead of just dealing with simple statements like "It is raining" or "The sky is blue", it allows us to make statements about objects and their properties, like "Every dog is a mammal" or "Some cats are black". Quantifiers act like a magnifying glass, allowing us to look at all or some objects at once.

7.4.2 Background Chaining:
Background chaining is a technique used in predicate logic to handle statements that are assumed to be true but not explicitly stated. These assumptions, or background knowledge, can be chained together to help infer new statements. For example, if we know that "All humans are mortal" and "Socrates is a human", we can infer that "Socrates is mortal" without explicitly stating it.

💡 Simple way to understand it:
Think of background chaining as a chain of dominoes. Each domino represents a statement, and when one falls, it knocks over the next one. In predicate logic, these dominoes can be statements about objects and their properties, and the chain can help us infer new statements.

7.4.3 Clause Form:
A formula in predicate logic is in clause form if it is a disjunction (OR) of literals, where each literal is either a predicate applied to variables or the negation (NOT) of a predicate applied to variables. Clause form is useful because it allows for efficient reasoning using the resolution principle, a method for logical inference that combines two clauses to produce a new clause.

💡 Simple way to understand it:
Think of clause form as a list of possible scenarios. Each scenario is a combination of statements about objects and their properties, or their negations. By combining these lists, we can find new scenarios that are the result of the combination of statements from both lists.

QUESTION #2  (10 Marks)  -  asked in 3 exam sittings [2025, 2024, 2023]
Question: explain in detail the architecture of a HDFs system.
----------------------------------------------------------------------
Model Answer:
HDFS

📘 As per your notes, the Hadoop Distributed File System (HDFS) is a distributed storage system designed to handle large datasets on commodity hardware. It stores data in smaller subsets called chunks or blocks, which are distributed across multiple nodes in a cluster. The system is designed for write-once, read-many times operations, providing faster read/write access and better availability and fault tolerance.

HDFS is a key component of the Hadoop ecosystem, and it is based on Google File System (GFS). The architecture of a HDFS system can be divided into two main components: the NameNode and DataNodes.

1. NameNode: The NameNode is the master node in the HDFS system. It manages the file system namespace, maintains the metadata for all files in the file system, and provides the interface for clients to access the file system. The NameNode is responsible for naming, organizing, and managing the data blocks across the DataNodes.

2. DataNodes: DataNodes are the worker nodes in the HDFS system. They store the actual data blocks and provide the data when requested by clients or the NameNode. Each DataNode runs a local file system and communicates with the NameNode to manage the data blocks it stores.

In the Hadoop high-level architecture, the HDFS Storage component consists of both the NameNode and DataNodes. The NameNode is responsible for managing the file system namespace and metadata, while the DataNodes store the actual data blocks.

💡 Simple way to understand it:
Think of a library where books are stored across multiple shelves in different rooms. The library's main desk (NameNode) keeps track of all the books (metadata), their locations (DataNodes), and manages the organization of the books (naming, organizing, and managing the data blocks). The readers (clients) can access the books (data) by asking the main desk (NameNode) for their location (DataNodes).

QUESTION #5  (6 Marks)  -  asked in 2 exam sittings [2024, 2022]
Question: explain Bayesian classification in detail.
----------------------------------------------------------------------
Model Answer:
BAYESIAN CLASSIFICATION

📘 As per your notes, Bayesian classification is a type of machine learning algorithm that belongs to the supervised learning category. It's based on Bayes' theorem, which allows for the calculation of conditional probabilities.

In Bayesian classification, the algorithm learns the probability distribution of the classes in the training data. For a new data point, it calculates the probability of that data point belonging to each class and assigns it to the class with the highest probability.

There are two main components in Bayesian classification: prior probabilities and conditional probabilities.

- Prior probabilities: These are the probabilities of each class before seeing any data. They can be estimated from the training data or provided by the user.

- Conditional probabilities: These are the probabilities of observing the data given that it belongs to a specific class. They are also estimated from the training data.

💡 Simple way to understand it: Think of Bayesian classification as a judge in a courtroom. The judge has prior beliefs about the guilt or innocence of the defendant (prior probabilities). The evidence presented in court (data) changes the judge's beliefs about the defendant's guilt (conditional probabilities). The judge then makes a decision based on the evidence and their prior beliefs (classification). The key difference is that the judge updates their beliefs as new evidence comes in, just like Bayesian classification updates its probabilities as it sees more data.

QUESTION #6  (10 Marks)  -  asked in 2 exam sittings [2024, 2023]
Question: What is clustering ? explain various clustering techniques.
----------------------------------------------------------------------
Model Answer:
CLUSTERING

📘 As per your notes, Clustering is a process that involves grouping similar objects together. It is an example of unsupervised learning, meaning it doesn't require predefined classes or labels. Instead, it identifies natural patterns or similarities among the data. Clustering can be used to segment data, similar to classification algorithms, but without any predefined classes.

In the context of a supermarket, clustering could be used to group items like butter, cheese, and milk under the "dairy products" category, as they share similar characteristics.

💡 A simple way to understand clustering is like organizing a library. Instead of having specific sections for fiction, non-fiction, and biographies, you group books based on their similarities, such as books with similar themes or authors.

Various clustering techniques include:

- K-means Clustering: This is one of the most popular clustering algorithms. It works by dividing the data into K clusters, where K is a user-defined number. Each data point belongs to the cluster with the nearest mean.

- Hierarchical Clustering: This technique builds a hierarchy of clusters, where each cluster is either a single data point or a group of data points that are very similar to each other. Hierarchical clustering can be either agglomerative (starting with individual data points and merging them) or divisive (starting with all data points in a single cluster and splitting them).

- DBSCAN (Density-Based Spatial Clustering of Applications with Noise): This algorithm groups together points that are close to each other in the feature space and have a high density of neighboring points. DBSCAN also identifies outliers or noise points that do not belong to any cluster.

Key differences between K-means and Hierarchical Clustering:

- K-means is a centroid-based method, where each cluster has a centroid (mean), while Hierarchical Clustering builds a hierarchy of clusters.
- K-means requires the number of clusters (K) to be specified beforehand, while Hierarchical Clustering does not require this information.
- K-means is faster for large datasets, but it may not perform well when the data is not spherical or when the clusters have different shapes and sizes. Hierarchical Clustering, on the other hand, can handle non-spherical clusters and varying cluster sizes, but it can be computationally expensive for large datasets.

QUESTION #2  (6 Marks)  -  asked in 3 exam sittings [2025, 2024, 2021]
Question: Differentiate CISC and RISC.
----------------------------------------------------------------------
Model Answer:
CISC AND RISC

📘 As per your notes, a Computer System can be classified as either a Complex Instruction Set Computer (CISC) or a Reduced Instruction Set Computer (RISC). The main difference between the two lies in the complexity and number of instructions they can handle.

CISC processors can execute complex instructions in a single clock cycle, but these instructions are more complex and require more resources. On the other hand, RISC processors can only execute simpler instructions, but they can do so in a single clock cycle, and the simpler instructions require fewer resources.

CISC uses many segments in its pipeline, with the longest segment requiring two or more clock cycles. In contrast, RISC can achieve pipeline segments, requiring just one clock cycle.

Question: Construct a 4-to-1 line multiplexer using logic gates. Explain its working procedure.
----------------------------------------------------------------------
Model Answer:
4-TO-1 LINE MULTIPLEXER

📘 As per your notes, a 4-to-1-line multiplexer is a circuit that receives binary data from four input lines (A0, A1, A2, A3) and directs it to a single output line (O) based on the selection of a particular input data line, determined by a set of selection inputs (S0, S1).

The 4-to-1-line multiplexer can be constructed using logic gates, specifically AND gates, OR gates, and an Inverter. The working procedure involves the following steps:

1. The selection inputs (S0, S1) are combined with the input data lines (A0, A1, A2, A3) using AND gates to create four separate product terms (P0, P1, P2, P3).

2. Each product term (P0, P1, P2, P3) is then combined with the corresponding bit of the selection line (S0, S1) using an OR gate.

3. The output of each OR gate is then passed through an Inverter to invert the polarity of the signal.

4. The inverted signals from the OR gates are then combined using another OR gate, which serves as the final output gate. The output of this OR gate is the selected input data line that is sent to the output line (O).

💡 A 4-to-1-line multiplexer can be thought of as a traffic intersection with four incoming roads (A0, A1, A2, A3) and one outgoing road (O). The selection inputs (S0, S1) act as traffic signals that allow only one road to send traffic to the outgoing road at a time. The AND gates act as the traffic lights, allowing traffic to pass only when both the road and the green light are present. The OR gates act as the intersection, combining the traffic from the allowed roads, and the Inverter acts as a one-way street, reversing the direction of the traffic.

MAP-REDUCE

📘 As per your notes, MapReduce is a programming model introduced by Google for processing large quantities of data. It expresses the computation as a series of Map and Reduce tasks. The model consists of four phases: Configure Map, Configure Reduce, While Condition Holds True Do, and Close. In the Map phase, the input data is processed and transformed into intermediate key-value pairs. In the Reduce phase, these intermediate key-value pairs are combined to produce the final output. The While Condition Holds True Do phase includes running MapReduce, applying a Combine operation to the result, updating the condition, and repeating the process if necessary. The Close phase signifies the end of the MapReduce job.

The Map phase is where raw data is transformed into standardized parts (intermediate key-value pairs), similar to how parts are manufactured in a factory. The Reduce phase is where these standardized parts are combined to create the final product (output). The While Condition Holds True Do phase ensures that the production line keeps running until all data is processed, and the Close phase signals the end of the production.

The Hadoop ecosystem is a collection of open-source software projects that support the MapReduce programming model. It includes Hadoop Distributed File System (HDFS), YARN, Hadoop MapReduce, and various other tools for data processing, storage, and management.

Some key components of the Hadoop ecosystem are:
- Hadoop Distributed File System (HDFS): A distributed file system designed to store large amounts of data across multiple commodity machines.

This method was first proposed in 1994 by Len Adleman, a renowned U.S. computer scientist who also contributed to the development of the RSA encryption algorithm.

The Hamiltonian circuit problem is a variant of the Hamiltonian path problem where the path must start and end at the same vertex and pass through all the other vertices exactly once. The Traveling Salesman problem is another related problem that involves finding the shortest tour through a given set of cities with known positive integer distances between them.

💡 Simple way to understand it:
Think of a Hamiltonian path as a route you take to visit every city in a country exactly once without revisiting any city. The Hamiltonian circuit problem is like finding a route that starts and ends at your home city, while the Traveling Salesman problem is like finding the shortest route to visit every city and return home. These problems are difficult to solve for large graphs or cities, but can be verified quickly once a solution is found.

QUESTION #1  (6 Marks)  -  asked in 3 exam sittings [2025, 2022, 2020]
Question: Discuss ACID properties of a transaction.
----------------------------------------------------------------------
Model Answer:
ACID Properties of a Database Transaction (6 Marks)

A transaction is a logical unit of work that contains one or more database operations (read/write). To maintain database integrity, every DBMS enforces the four ACID properties:

1. Atomicity ("All or Nothing"):
   - Ensures that either all operations of the transaction are executed successfully and committed, or none of them take effect.
   - If a failure occurs mid-transaction, all changes are rolled back to the pre-transaction state.
   - DBMS Component: Managed by the Transaction Manager and Recovery Subsystem using write-ahead transaction logs (UNDO logs).

2. Consistency (Preserving Invariants):
   - A transaction must transform the database from one valid consistent state to another consistent state satisfying all integrity constraints (e.g., primary keys, foreign keys, balance >= 0).
   - If a transaction violates any constraint, it is aborted and rolled back.
   - DBMS Component: Enforced by the Integrity Subsystem and application logic.

3. Isolation (Concurrent Execution Separation):
   - Multiple transactions executing concurrently must execute without interfering with each other. The intermediate state of a transaction remains invisible to other concurrently executing transactions.
   - Prevents concurrency anomalies: Dirty Reads, Non-repeatable Reads, and Phantom Reads.
   - DBMS Component: Enforced by the Concurrency Control Subsystem using Locking protocols (2PL) or Timestamp Ordering.

4. Durability (Permanence of Committed Changes):
   - Once a transaction commits successfully, its updates persist permanently in non-volatile storage, even in the event of an immediate system crash or power outage.
   - DBMS Component: Enforced by the Recovery Manager using REDO logs and write-ahead logging (WAL).

----------------------------------------
Illustrative Real-World Example (Bank Fund Transfer):
Transferring ₹5,000 from Account A (₹20,000) to Account B (₹10,000):
START TRANSACTION;
UPDATE Accounts SET balance = balance - 5000 WHERE acc_no = 'A';
UPDATE Accounts SET balance = balance + 5000 WHERE acc_no = 'B';
COMMIT;
- Atomicity: If power fails after debiting A, B is not credited; rollback restores ₹5,000 to A.
- Consistency: Total money across A and B remains ₹30,000 before and after transaction.
- Isolation: A concurrent balance inquiry cannot see A debited before B is credited.
- Durability: Once COMMIT executes, ₹15,000 in both accounts survives a server restart.

Question: Write a note on hashing techniques.
----------------------------------------------------------------------
Model Answer:
Hashing Techniques in DBMS (6 Marks)

Hashing is a direct data access technique that maps search key values directly to storage bucket addresses using a mathematical hash function h(K), achieving average O(1) search, insert, and delete complexity.

1. Static Hashing:
- The number of bucket addresses M is fixed at database creation time.
- Hash function: h(K) = K mod M.
- Bucket Overflow Problem: When a record hashes to a bucket that is already full.
  - Handled via Open Hashing (Chaining / Overflow Buckets): Overflow linked lists attached to the primary bucket.
  - Handled via Closed Hashing (Linear/Quadratic Probing): Searches for the next available bucket sequentially.
- Limitation: Poor scalability when databases grow or shrink significantly.

2. Dynamic Hashing (Extendible & Linear Hashing):
Allows the hash table structure to grow and shrink dynamically without requiring complete re-hashing of all records.

- Extendible Hashing:
  - Uses an in-memory directory of pointers to disk buckets.
  - Global Depth (d): Number of bits used to index the directory (2^d directory entries).
  - Local Depth (d' <= d): Number of bits shared by records inside a specific bucket.
  - When a bucket overflows:
    - If d' = d: Directory doubles in size (d <- d + 1).
    - If d' < d: Only the overflowing bucket splits into two; local depths increment to d'+1; directory does not double.
- Linear Hashing:
  - Does not use a directory. Splits buckets linearly in round-robin order using a split pointer, maintaining an average storage utilization of ~75-80%.

Summary Comparison:
Parameter | Static Hashing | Extendible Hashing | Linear Hashing
Bucket Count | Fixed | Dynamic (2^d directory) | Dynamic (split pointer)
Directory Overhead | None | Yes (Memory directory) | None
Re-hashing Overhead | Massive when full | Localized to split bucket | Incremental

Schema and 3-Schema Architecture in DBMS (6 Marks)

1. Definition of Schema:
A Database Schema is the overall structural design and skeleton of the database, specifying tables, fields, data types, constraints, and relationships. It is stored in the data dictionary (system catalog) and rarely changes, whereas the data stored at a particular moment is termed the Database Instance.

2. Three-Schema (ANSI/SPARC) Architecture:
The primary objective is to separate user applications from the physical database, achieving Data Independence.

+-----------------------------------------------------------+
|              EXTERNAL LEVEL (User Views)                  |
|   [ View 1: Student ]      [ View 2: Accounts ]  [ View 3 ]|
+-----------------------------------------------------------+
                             |
                   External / Conceptual Mapping
                             |
+-----------------------------------------------------------+
|              CONCEPTUAL LEVEL (Logical Schema)            |

+-----------------------------------------------------------+
                             |
                  Conceptual / Internal Mapping
                             |
+-----------------------------------------------------------+

|   Storage Structures, Record Formats, B+ Trees, Hashing   |
+-----------------------------------------------------------+
                             |
                 [ Physical Database Storage ]

1. External Level (Sub-schemas / Views):
   - The view closest to the end-users. Each user group views only the subset of data relevant to their role, hiding confidential fields (e.g., students view marks, HR views salary).

- Logical Data Independence: Ability to modify the Conceptual Schema (e.g. adding a new table or attribute) without altering existing External Views or application programs.

Question: Explain domain constraint, key constraint and referential integrity constraints.
----------------------------------------------------------------------
Model Answer:
Relational Integrity Constraints (6 Marks)

Integrity constraints are rules enforced by the DBMS to ensure database accuracy, consistency, and validity during insert, update, and delete operations.

1. Domain Constraint:
- Specifies that the value of each attribute A in any tuple must be an atomic value belonging to the predefined domain dom(A).
- Enforces data type, format, permissible range, and nullability.
- Examples in SQL:
  age INT CHECK (age >= 18 AND age <= 60),
  gender CHAR(1) CHECK (gender IN ('M', 'F', 'O')),
  email VARCHAR(100) NOT NULL
- Violation: Attempting to insert "abc" into an INT field or age = 15 triggers a constraint violation error.

2. Key Constraint:
- States that no two distinct tuples in any relation state r(R) can have identical values for the Primary Key or Candidate Key attribute(s).
- Superkey: A set of attributes that uniquely identifies a tuple.
- Candidate Key: A minimal superkey (no redundant attributes).
- Primary Key: The chosen candidate key; strictly requires Uniqueness and Entity Integrity (Primary key attributes can never be NULL).
- SQL Example:
  student_id VARCHAR(10) PRIMARY KEY

3. Referential Integrity Constraint:
- Enforced between two relations (Referencing relation R_1 and Referenced relation R_2).
- A tuple in R_1 has a Foreign Key (FK) that references the Primary Key (PK) of R_2.
- The foreign key value must either:
  1. Match an existing primary key value in the referenced relation, or
  2. Be NULL (if nulls are allowed).
- Referential Action Rules:
  - ON DELETE CASCADE: Deleting referenced parent tuple automatically deletes matching child tuples.
  - ON DELETE RESTRICT / NO ACTION: Rejects deletion of parent tuple if child records exist.
  - ON DELETE SET NULL: Sets child foreign key to NULL.
- SQL Example:
  FOREIGN KEY (dept_id) REFERENCES Department(dept_id)
      ON DELETE RESTRICT ON UPDATE CASCADE

Question: Explain Two Phase Locking Protocol used in concurrency control.
----------------------------------------------------------------------
Model Answer:
Two-Phase Locking (2PL) Protocol (10 Marks)

The Two-Phase Locking (2PL) protocol is a concurrency control mechanism that guarantees Conflict Serializability by enforcing strict rules on when transactions may acquire and release locks.

1. Lock Types:
- Shared Lock (S): Acquired for reading data items (read_lock). Multiple transactions can hold shared locks concurrently on the same item.
- Exclusive Lock (X): Acquired for writing data items (write_lock). Only one transaction can hold an exclusive lock; all other lock requests are blocked.

2. The Two Phases of 2PL:
Every transaction must execute in two distinct phases:

Number of
Locks Held
   ^
   |        Lock Point
   |            *
   |          /   \
   |         /     \
   |        /       \
   |       /         \
   +-------------------------> Time
     Growing Phase   Shrinking Phase
     (Locks Acquired) (Locks Released)

1. Phase 1: Growing Phase (Expanding Phase):
   - The transaction may obtain new locks (both Shared and Exclusive) or upgrade an S lock to an X lock.
   - Crucial Rule: The transaction CANNOT release any lock during this phase.
2. Lock Point:
   - The exact moment when the transaction has acquired the final lock it requires. Serializability order is determined by the order of lock points.
3. Phase 2: Shrinking Phase (Contracting Phase):
   - The transaction may release locks or downgrade an X lock to an S lock.
   - Crucial Rule: The transaction CANNOT acquire any new lock once it releases its first lock.

3. Variations of 2PL:
- Basic 2PL: Guarantees conflict serializability, but is vulnerable to Cascading Aborts and Deadlocks.
- Strict 2PL:
  - Requires all Exclusive (X) locks to be held until the transaction commits or aborts.
  - Guarantees Strict Schedules and completely eliminates cascading rollbacks.
- Rigorous 2PL:
  - Requires all Shared (S) AND Exclusive (X) locks to be held until transaction commit. Easiest to implement.

4. Limitations of 2PL:
- Deadlocks: Concurrent transactions waiting for locks held by each other can form cycles (e.g. T_1 holds A waiting for B, while T_2 holds B waiting for A). Resolved via Wait-For Graphs or Timeout mechanisms.

p(F∣E) = p(E∣F) * p(F) / p(E)

where:
- p(F∣E) is the probability of hypothesis F given evidence E
- p(E∣F) is the probability of evidence E given hypothesis F
- p(F) is the prior probability of hypothesis F
- p(E) is the total probability of evidence E (sum of probabilities of all possible hypotheses that could generate the evidence)

The theorem can also be rewritten as:

p(E∣F) * p(F) = p(E∣F) * p(F) + p(E∣F') * p(F')

where F' represents the complement of F (all possible hypotheses except F).

💡 A simple way to understand Bayes' theorem is by imagining a coin toss. Suppose you have a biased coin that lands on heads 70% of the time and tails 30% of the time. If you toss the coin once and it lands on heads, Bayes' theorem helps you update your belief about the coin's bias based on the new evidence (the toss result). The theorem calculates the updated probability of the coin being biased towards heads (F) given the evidence (the toss result).

Step 1: [Check for Stack Overflow]
        If TOP = MAXSIZE then:

            Exit
Step 2: [Increment Top Pointer]
        TOP := TOP + 1
Step 3: [Insert Element]
        STACK[TOP] := ITEM
Step 4: [Success]
        Write "Item pushed successfully"
        Exit
Time Complexity: O(1) | Space Complexity: O(1)

2. POP Operation:
Removes and returns the topmost element ITEM from the stack.
Algorithm POP(STACK, TOP, ITEM)
Step 1: [Check for Stack Underflow]
        If TOP = 0 then:
            Write "Error: Stack Underflow"
            Exit
Step 2: [Retrieve Top Element]
        ITEM := STACK[TOP]
Step 3: [Decrement Top Pointer]
        TOP := TOP - 1
Step 4: [Return Value]
        Return ITEM
        Exit
Time Complexity: O(1) | Space Complexity: O(1)

CIRCULAR LINKED LIST

 // C code for insertion and deletion operations for a circular linked list (as per Algorithm 5.14)

#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int info;
    struct Node* link;
} Node;

Node* start, *avail;

void FINDBHL(int info, Node* link, Node* start, int item, Node** loc, Node** locp) {
    *locp = NULL;
    *loc = start;
    while (*loc != avail) {
        if ((*loc)->info == item) {
            *locp = (*loc)->link;
            return;
        }
        *locp = *loc;
        *loc = (*loc)->link;
    }
}

void InsertCircular(int info) {
    Node* newNode = (Node*)malloc(sizeof(Node));
    newNode->info = info;
    newNode->link = avail;

    if (start == NULL) {
        start = newNode;
        avail = start;
        avail->link = start;
    } else {
        FINDBHL(info, start, start, info, NULL, &avail);
        newNode->link = avail->link;
        avail->link = newNode;
    }
}

void DeleteCircular(int item) {
    Node* loc, *locp;
    FINDBHL(item, start, start, item, &loc, &locp);

    if (loc == avail) {
        printf("List is empty\n");
        return;
    }

    if (loc == start)
        start = loc->link;
    avail->link = loc->link;
    free(loc);
}

The InsertCircular function adds a new node to the list, and the DeleteCircular function removes the first node containing the specified item. The FINDBHL function is a helper function that finds the location of a node and its preceding node in the circular linked list.

QUESTION #8  (5 Marks)  -  asked in 2 exam sittings [2024, 2022]
Question: Explain the technique of collision resolution with open addressing.
----------------------------------------------------------------------
Model Answer:
Collision Resolution Using Open Addressing (5 Marks)

In hashing, a collision occurs when two distinct keys hash to the same bucket address (h(k_1) = h(k_2)). In Open Addressing (Closed Hashing), all elements are stored directly inside the hash table array without linked lists. When a collision occurs, alternative cells are probed until an empty slot is found.

1. Linear Probing:
- Checks sequential slots: h(k, i) = (h'(k) + i) mod M, for i = 0, 1, 2, ..., M-1.
- Advantage: Excellent CPU cache locality.
- Disadvantage: Suffers from Primary Clustering (long blocks of occupied slots build up, drastically increasing average probe time).

2. Quadratic Probing:
- Uses a quadratic function of probe number:
  h(k, i) = (h'(k) + c_1 i + c_2 i^2) mod M
- Eliminates primary clustering, but can lead to Secondary Clustering (keys with the same initial hash follow identical probe sequences).

3. Double Hashing:
- Uses two independent hash functions h_1(k) and h_2(k):
  h(k, i) = (h_1(k) + i x h_2(k)) mod M
- Condition: h_2(k) must be relatively prime to M (e.g. M is prime).
- Advantage: Produces near-ideal uniform distribution; minimizes clustering anomalies.

Question: What are Asymptotic Notations ? Explain with an example.
----------------------------------------------------------------------
Model Answer:
Asymptotic Notations in Algorithm Analysis (6 Marks)

Asymptotic notations are mathematical tools used to describe the limiting behavior and growth rate of an algorithm's running time or memory usage as the input size n approaches infinity (n -> infinity).

1. Big-O Notation (O - Asymptotic Upper Bound):
- Represents the worst-case performance (maximum time an algorithm can take).
- Formal Definition: f(n) = O(g(n)) if there exist positive constants c > 0 and n_0 >= 1 such that:
  0 <= f(n) <= c x g(n) quad for all n >= n_0
- Example: If f(n) = 3n^2 + 5n + 2, choose c = 4 and n_0 = 6, so f(n) <= 4n^2, meaning f(n) = O(n^2).

2. Big-Omega Notation (Omega - Asymptotic Lower Bound):
- Represents the best-case performance (minimum time guaranteed).
- Formal Definition: f(n) = Omega(g(n)) if there exist positive constants c > 0 and n_0 >= 1 such that:
  0 <= c x g(n) <= f(n) quad for all n >= n_0
- Example: 3n^2 + 5n >= 3n^2 for all n >= 1, so f(n) = Omega(n^2).

3. Big-Theta Notation (Theta - Asymptotic Tight Bound):
- Bounds the function from both above and below within constant factors.
- Formal Definition: f(n) = Theta(g(n)) if there exist positive constants c_1, c_2 > 0 and n_0 >= 1 such that:
  0 <= c_1 x g(n) <= f(n) <= c_2 x g(n) quad for all n >= n_0
- Example: Linear search on an array of size n has worst-case O(n), best-case Omega(1), and average-case Theta(n).

The Readers-Writers Problem of Synchronization (6 Marks)

1. Problem Statement:

2. Synchronization Primitives:
- semaphore rw_mutex = 1; // Controls mutual exclusion for writers and first/last reader
- semaphore mutex = 1;    // Protects updates to read_count
- int read_count = 0;     // Number of active reader processes

3. Reader Process Pseudocode:
do {
    wait(mutex);
    read_count++;
    if (read_count == 1)
        wait(rw_mutex); // First reader locks out all writers
    signal(mutex);

    // Reading performed here...

    wait(mutex);
    read_count--;
    if (read_count == 0)
        signal(rw_mutex); // Last reader releases lock for writers
    signal(mutex);
} while (TRUE);

4. Writer Process Pseudocode:
do {
    wait(rw_mutex);

    // Writing / Modifying data performed here...

    signal(rw_mutex);
} while (TRUE);

5. Starvation Concern:
In the first readers-writers solution shown above (Reader Preference), continuous incoming readers can keep rw_mutex locked indefinitely, causing Writer Starvation.

Semaphores and the Dining-Philosophers Problem (5 Marks)

1. Definition of Semaphore:
A Semaphore is an integer synchronization variable accessed only through two standard atomic operations:

  wait(S) {
      while (S <= 0) ; // busy wait (or block process in queue)
      S--;
  }
- signal(S) (or V(S)):
  signal(S) { S++; }
Types: Binary Semaphore (Mutex) (range 0 to 1) and Counting Semaphore (unbounded range).

2. Dining Philosophers Problem:
Five philosophers sit around a circular table with 5 bowls of rice and 5 chopsticks. A philosopher alternately thinks and eats. To eat, a philosopher requires both the left and right chopsticks.

3. Semaphore Solution & Deadlock Prevention:
Represent each chopstick as a semaphore: semaphore chopstick[5] = {1, 1, 1, 1, 1};

Naïve Solution: Each philosopher picks left chopstick, then right chopstick.
Deadlock Hazard: If all 5 philosophers get hungry simultaneously and pick their left chopstick, all chopsticks are held and none can pick their right chopstick.

Deadlock-Free Asymmetric Solution:
An odd philosopher picks left first then right; an even philosopher picks right first then left:
void philosopher(int i) {
    while (1) {
        think();
        if (i % 2 == 0) {
            wait(chopstick[(i + 1) % 5]); // pick right
            wait(chopstick[i]);           // pick left
        } else {
            wait(chopstick[i]);           // pick left
            wait(chopstick[(i + 1) % 5]); // pick right
        }
        eat();
        signal(chopstick[i]);
        signal(chopstick[(i + 1) % 5]);
    }
}

Question: Write short notes on Rice theorem and Halting problem.
----------------------------------------------------------------------
Model Answer:
Rice's Theorem & The Halting Problem (6 Marks)

1. Rice's Theorem:
- Statement: Any non-trivial semantic property of the language recognized by a Turing machine is Undecidable.
- A property P of recursively enumerable languages is non-trivial if at least one RE language satisfies P and at least one RE language does not satisfy P.
- Implication: Questions like "Does Turing machine M accept an empty language?", "Does M accept a regular language?", or "Does M accept all strings?" cannot be solved by any general algorithm.

2. The Halting Problem of Turing Machine:
- Statement: Given a description of an arbitrary Turing machine M and input w, determine whether M will eventually halt on input w or loop forever:
  H = { < M, w > | M halts on input w }
- Alan Turing's Proof (by Contradiction / Diagonalization):
  - Assume a decider H exists that returns TRUE if M(w) halts and FALSE if it loops.
  - Construct a new machine D: On input < M >, run H(< M, < M > >). If H says halts, D loops forever; if H says loops, D halts immediately.
  - Now run D on its own description: D(< D >).
    - If D(< D >) halts => D must loop.
    - If D(< D >) loops => D must halt.
  - A logical contradiction! Thus, no such decider H can exist. The Halting Problem is Undecidable.

Model Answer:
Halting Problem of a Turing Machine (6 Marks)

Statement: Given the description <M> of an arbitrary Turing machine M and an input string w, decide whether M halts on w.
HALT = { <M, w> | M halts on input w }

The Halting Problem is undecidable: no Turing machine (algorithm) can answer this correctly for every pair <M, w>. HALT is recursively enumerable (simulate M on w and accept if it halts) but not recursive.

Proof (by contradiction / diagonalization):
1. Assume a decider H exists: H(<M, w>) = accept if M halts on w, reject otherwise.
2. Build a machine D that on input <M> runs H on <M, <M>>. If H accepts (M halts on <M>), D loops forever. If H rejects, D halts.
3. Run D on its own description <D>:
   - if D halts on <D>, then by construction D loops on <D>;
   - if D loops on <D>, then by construction D halts on <D>.
4. Both cases contradict, so H cannot exist.

Significance: it is the first proven undecidable problem. Other problems are shown undecidable by reducing the Halting Problem to them (for example the Rice's theorem properties, emptiness of a Turing machine language, and equivalence of two Turing machines).

Question: Minimize the following DFA.
----------------------------------------------------------------------
Model Answer:
Minimization of a DFA (Table-Filling / Myhill-Nerode method) (6 Marks)

Note: the DFA diagram of this question is not part of the extracted text, so the standard method is given with a worked example. Apply the same steps to the given DFA.

Method:
1. Remove unreachable states.
2. List all pairs of states (p, q). Mark a pair as distinguishable if one state is final and the other is not.
3. Repeat: mark (p, q) if for some input symbol a the pair (delta(p,a), delta(q,a)) is already marked.
4. Stop when no new pair is marked. Unmarked pairs are equivalent; merge them into one state.
5. Build the minimal DFA from the merged classes (start state = class of the old start state, final = classes of final states).

Example: states q0 (start), q1, q2, q3 (final). q0 -0-> q1, q0 -1-> q2; q1 and q2 go to q3 on both 0 and 1; q3 loops on 0 and 1.
- Step 2 marks (q0,q3), (q1,q3), (q2,q3).
- (q0,q1): on 0 goes to (q1,q3), which is marked, so mark it. (q0,q2): on 0 goes to (q1,q3), marked, so mark it.
- (q1,q2): on 0 and on 1 goes to (q3,q3), the same state, so it stays unmarked: q1 is equivalent to q2.

Minimal DFA: {q0}, {q1,q2}, {q3}, with 3 states instead of 4.

QUESTION #6  (10 Marks)  -  asked in 2 exam sittings [2022, 2021]
Question: Define Recursive and Recursively enumerable languages and prove that the union of two recursive languages is recursive.
----------------------------------------------------------------------
Model Answer:
Recursive and Recursively Enumerable Languages (10 Marks)

Recursive language (decidable): a language L is recursive if there is a Turing machine M that halts on every input and accepts exactly the strings of L (it accepts strings in L and rejects strings not in L).

Recursively enumerable (RE) language: a language L is RE if there is a Turing machine M that accepts exactly the strings of L. On a string not in L, M may reject or loop forever.

Relation: every recursive language is RE, but not every RE language is recursive. For example, the Halting language HALT is RE but not recursive.

Theorem: the union of two recursive languages is recursive.

Proof: Let L1 and L2 be recursive. Then there are Turing machines M1 and M2 that decide L1 and L2, and both halt on every input.
Construct M. On input w:
1. Run M1 on w. If M1 accepts, accept.
2. Otherwise M1 has rejected (it always halts). Run M2 on w. If M2 accepts, accept; otherwise reject.

Correctness:
- M halts on every input, because M1 and M2 each halt.
- M accepts w exactly when w is in L1 or w is in L2, that is, when w is in the union of L1 and L2.

So M decides L1 union L2, and the union is recursive. (Recursive languages are also closed under intersection and complement.)

QUESTION #7  (6 Marks)  -  asked in 2 exam sittings [2022, 2021]
Question: Explain DFA and NFA with suitable examples.
----------------------------------------------------------------------
Model Answer:
DFA and NFA with Examples (6 Marks)

A finite automaton is a 5-tuple (Q, Sigma, delta, q0, F): states, input alphabet, transition function, start state, set of final states.

DFA (Deterministic Finite Automaton): for every state and input symbol there is exactly one next state, delta: Q x Sigma -> Q.
Example: strings over {0,1} with an even number of 0s. States q0 (start, final) and q1.
delta(q0,0) = q1, delta(q0,1) = q0, delta(q1,0) = q0, delta(q1,1) = q1.

NFA (Nondeterministic Finite Automaton): a state may have zero, one or several next states for a symbol, delta: Q x Sigma -> 2^Q (and moves on epsilon are allowed in an epsilon-NFA). A string is accepted if at least one path ends in a final state.
Example: strings over {0,1} ending in 01. States q0 (start), q1, q2 (final).
delta(q0,0) = {q0,q1}, delta(q0,1) = {q0}, delta(q1,1) = {q2}.

Key differences:
- A DFA has exactly one move per symbol; an NFA may have many or none.
- An NFA is usually smaller and easier to design; a DFA is easier to implement (one path).
- Both accept exactly the regular languages. Every NFA with n states can be converted to an equivalent DFA with at most 2^n states (subset construction).

QUESTION #8  (6 Marks)  -  asked in 2 exam sittings [2022, 2021]
Question: State and prove pumping lemma for regular languages and prove that the following language is not regular. L = {ωω|ω ∈ {a, b}*}
----------------------------------------------------------------------
Model Answer:
Pumping Lemma for Regular Languages (6 Marks)

Statement: If L is a regular language, there is a constant p >= 1 (the pumping length) such that every string w in L with |w| >= p can be written as w = xyz where
1. |y| >= 1,
2. |xy| <= p,
3. x y^i z is in L for every i >= 0.

Proof: Let a DFA with p states accept L. Take w in L with |w| >= p. While reading the first p symbols the DFA visits p + 1 states, so by the pigeonhole principle some state repeats. Let x be the part read before the first visit of that state, y the part read in the loop back to it, and z the rest. The loop y can be repeated any number of times, or skipped, and the DFA still ends in the same final state. Hence x y^i z is in L.

To prove L = { ww | w in {a,b}* } is not regular:
1. Assume L is regular with pumping length p.
2. Choose s = a^p b a^p b. It is in L (w = a^p b) and |s| >= p.
3. Since |xy| <= p, y lies inside the first block of a's: y = a^k with k >= 1.
4. Pump with i = 2: the string becomes a^(p+k) b a^p b.
5. This string has exactly two b's, so if it were of the form uu, each u would contain one b and end with it. The first u would be a^(p+k) b, of length p+k+1, and the second u = a^p b has length p+1. These differ because k >= 1, so the string is not of the form uu.
6. So x y^2 z is not in L, contradicting the lemma. Hence L is not regular.

QUESTION #9  (5 Marks)  -  asked in 2 exam sittings [2025, 2022]
Question: Check whether the following grammar is ambiguous. S → iCtS/iCtSeS/a C → b
----------------------------------------------------------------------
Model Answer:
Ambiguity of the grammar (5 Marks)

Grammar: S -> iCtS | iCtSeS | a,  C -> b
(i = if, t = then, e = else; this is the classic dangling-else grammar.)

A grammar is ambiguous if some string has two or more different parse trees (equivalently, two different leftmost derivations).

Take the string w = ibtibtaea.

Leftmost derivation 1 (the else belongs to the inner if):
S => iCtS => ibtS => ibt iCtSeS => ibtibtSeS => ibtibtaeS => ibtibtaea

Leftmost derivation 2 (the else belongs to the outer if):
S => iCtSeS => ibtSeS => ibt iCtS eS => ibtibtSeS => ibtibtaeS => ibtibtaea

The two derivations use different productions at the first step (S -> iCtS versus S -> iCtSeS), so they give two different parse trees for the same string.

Therefore the grammar is ambiguous.

QUESTION #10  (6 Marks)  -  asked in 2 exam sittings [2025, 2023]
Question: Convert the following grammar into PDA. S → aABC A → aB | a B → bA | b C → a
----------------------------------------------------------------------
Model Answer:
Conversion of a CFG into a PDA (6 Marks)

Given: S -> aABC,  A -> aB | a,  B -> bA | b,  C -> a

Construction (acceptance by empty stack): M = ({q}, {a,b}, {S,A,B,C,a,b}, delta, q, S), with start stack symbol S.
1. For every production X -> alpha, add delta(q, epsilon, X) containing (q, alpha). The variable on top of the stack is replaced by the right-hand side.
2. For every terminal t, add delta(q, t, t) = {(q, epsilon)}. The input symbol is matched with the top of the stack and popped.

Transitions:
delta(q, epsilon, S) = {(q, aABC)}
delta(q, epsilon, A) = {(q, aB), (q, a)}
delta(q, epsilon, B) = {(q, bA), (q, b)}
delta(q, epsilon, C) = {(q, a)}
delta(q, a, a) = {(q, epsilon)}
delta(q, b, b) = {(q, epsilon)}

Example: the string aaba, derived as S => aABC => aaBC => aabC => aaba.
Stack (top at left): S -> aABC -> read a -> ABC -> aBC -> read a -> BC -> bC -> read b -> C -> a -> read a -> empty.
The stack is empty after the whole input is read, so the string is accepted.

QUESTION #12  (5 Marks)  -  asked in 2 exam sittings [2025, 2024]
Question: State and prove pumping lemma for context free languages. Show that L = {aⁿbⁿcⁿ/n>=1} is not context free.
----------------------------------------------------------------------
Model Answer:
Pumping Lemma for Context-Free Languages (5 Marks)

Statement: If L is a context-free language, there is a constant p >= 1 such that every string z in L with |z| >= p can be written as z = u v w x y where
1. |vwx| <= p,
2. |vx| >= 1 (v and x are not both empty),
3. u v^i w x^i y is in L for every i >= 0.

Proof idea: take a grammar for L in Chomsky Normal Form with k variables and let p = 2^k. A parse tree of a string of length >= p has height more than k, so some root-to-leaf path contains a variable A twice. Then A =>* vAx and A =>* w, so the part generated by the upper A can be repeated (v and x pumped together) or removed, and the result is still in L.

To show L = { a^n b^n c^n | n >= 1 } is not context free:
1. Assume L is context free with pumping length p.
2. Choose z = a^p b^p c^p, which is in L with |z| >= p.
3. Since |vwx| <= p, the part vwx cannot contain both a's and c's (the b's in between are p symbols long). It lies in one block or spans two neighbouring blocks.
4. Pump with i = 2. Because |vx| >= 1, at least one letter increases in number. At most two of the three letters appear in vx, so the third keeps its old count.
5. So the counts of a, b and c are no longer equal and u v^2 w x^2 y is not in L, a contradiction.

Hence L is not context free.

GET VS POST METHODS IN AJAX REQUEST

- POST method: This method sends the data as the body of the HTTP request. The data is not visible in the URL and cannot be bookmarked or shared easily. It has no limit on the amount of data that can be sent. POST requests are often used for sending data to the server, such as submitting a form.
