## NORMALIZATION

📘 As per your notes, Normalization in DBMS (Database Management System) is a process used to organize and structure data in a relational database to minimize redundancy and dependency, improve data integrity, and enhance the efficiency of database operations. The normalization procedure involves several normal forms, each designed to eliminate specific types of redundancies and anomalies.

1. First Normal Form (1NF): Ensures each table has unique columns, all columns contain atomic (indivisible) values, and each row is unique.
2. Second Normal Form (2NF): Requires that every non-key attribute is fully dependent on the primary key. In other words, all partial dependencies must be eliminated.
3. Third Normal Form (3NF): Eliminates transitive dependencies, meaning that non-key attributes should not depend on other non-key attributes.
4. Boyce-Codd Normal Form (BCNF): Ensures that every functional dependency is a full dependency, i.e., every determinant is a candidate key.
5. Fourth Normal Form (4NF): Eliminates multi-valued dependencies (MVDs), where a single attribute can have multiple values for a single primary key.

💡 Simple way to understand it:
Think of normalization as organizing a messy bookshelf. Initially, the books are mixed up, with some books having multiple copies, some books missing pages, and some books having pages from other books inserted. Normalization is like sorting the books, removing duplicates, and organizing them in a way that each book has all its pages and no extra pages. Each normal form represents a step in this process, making the bookshelf (database) more organized and efficient.

## QUICK SORT

📘 What is Quick Sort:
Quick Sort is a divide-and-conquer sorting algorithm that partitions a list into smaller sublists around a pivot element. It recursively sorts these sublists until the entire list is sorted. The algorithm's time efficiency is O(n log n) in all cases, with the number of key comparisons being very close to the theoretical minimum.

## STACK

📘 A stack is a linear data structure that follows the Last-In-First-Out (LIFO) principle. It operates based on the principle of a stack of plates, where the last plate added is the first one to be removed. In a computer, it is used to manage function calls, variables, and memory allocation.

💡 Think of a stack as a pile of plates. When you add a new plate (push), it goes on top of the existing ones. To get the top plate (pop), you have to remove all the plates above it first.

- Memory Stack: A region of the computer's memory used to store temporary data during the execution of a program. It is managed by the system and is used for function calls and local variables.
- Register Stack: A smaller, faster version of the memory stack, located in the CPU. It stores the addresses of the memory stack for function calls and returns.

Key differences:
- Memory Stack is a larger, slower data structure, managed by the system, while the Register Stack is smaller, faster, and managed by the CPU.
- The Memory Stack stores actual data, while the The Register Stack stores the addresses of the memory stack for function calls and returns, not the actual data. This allows the CPU to quickly access the necessary information during function calls and returns, improving the efficiency of the program.

- Operating System Stack: A stack used by the operating system to manage system calls, interrupts, and exceptions. It is a crucial part of the system's multitasking capabilities.

By understanding and utilizing stacks effectively, programmers can create more efficient and organized code.

## ARRAY VS LINKED LIST

📘 As per your notes, an array and a linked list are both data structures used to store and organize data, but they differ in their structure and access methods.

An array is a collection of elements of the same data type, stored in contiguous memory locations. Each element can be accessed directly using an index, which is a number that corresponds to the position of the element in the array. For example, an array named 'salary' can store the salaries of multiple employees, and each salary can be accessed using an index that corresponds to the employee's position in the array.

A linked list, on the other hand, is a collection of data items, called nodes, that are connected to each other through pointers. Each node contains a data item and a pointer to the next node in the list. The last node in the list, called the tail, points to a special node called NIL, which indicates the end of the list.

💡 Simple way to understand it:

Think of an array as a row of lockers in a school, where each locker has a unique number and contains a student's belongings. You can directly access a student's belongings by knowing their locker number. On the other hand, a linked list is like a chain of lockers where each locker has a key that points to the next locker in the chain. You need to follow the keys to find a specific student's belongings.

Key differences:

- Access method: Arrays can be accessed directly using an index, while linked lists require traversing through the pointers to find the desired data.
- Memory allocation: Arrays require a fixed amount of memory to be allocated at the start, while linked lists can dynamically allocate memory as needed.
- Insertion and deletion: Inserting or deleting an element in an array requires shifting other elements, which can be time-consuming for large arrays. In a linked list, insertion or deletion only requires changing the pointers, making it more efficient for dynamic data structures.
- Efficiency: Arrays provide constant-time access to elements (O(1)), while linked lists require linear time (O(n)) to access an element at a specific position. However, linked lists provide constant-time insertion and deletion (O(1)), while arrays require linear time (O(n)) for these operations.

## HASHING

📘 As per your notes, Hashing is a method used for data storage and retrieval, particularly in computer science. It involves using a mathematical function to map keys (like words or numbers) to integers, which are then used as indices in an array or table. There are two main types of hashing: Open Hashing (also known as Separate Chaining) and Closed Hashing (also known as Open Addressing).

In Open Hashing, keys are stored in linked lists attached to cells of a hash table. Each list contains all the keys hashed to its cell. For instance, if we have a list of words: A, FOOL, AND, HIS, MONEY, ARE, SOON, PARTED, the hash function would map each word to an integer, and the linked list at that integer's position in the hash table would store the word.

💡 Simple way to understand it: Think of a phone book where each name is a key. Instead of having a separate page for each name, we put all names starting with the same letter on the same page (cell in the hash table). If the page is full, we add a new page (linked list) for that letter. This is Open Hashing, where the linked lists act as pages for overflow.

Key differences between Open Hashing and Closed Hashing:

- In Open Hashing, when a cell is full, we create a new linked list (page) for overflow. In Closed Hashing, when a cell is full, we try to find an empty cell elsewhere in the table (using probing techniques).
- Open Hashing uses linked lists for handling collisions (when two keys map to the same integer), while Closed Hashing uses various probing techniques to find an empty cell.
- Open Hashing is generally easier to implement but can have higher space complexity due to the linked lists, while Closed Hashing can have higher time complexity due to probing.

- A stack follows the Last-In-First-Out (LIFO) principle, while a queue follows the FIFO principle.
- Stacks are primarily used for function call and return mechanisms, while queues are used for managing tasks and network traffic.

## WRITE PROGRAM BINARY SEARCH

 // C program for binary search

```c
#include <stdio.h>

int binarySearch(int arr[], int l, int r, int x) {
    if (r >= l) {
        int mid = l + (r - l) / 2;

        // If the element is present at the middle itself
        if (arr[mid] == x)
            return mid;

        // If element is smaller than mid, it can only be present in left subarray
        if (arr[mid] > x)
            return binarySearch(arr, l, mid - 1, x);

        // Else the element can only be present in right subarray
        return binarySearch(arr, mid + 1, r, x);
    }

    // We reach here when element is not present in array
    return -1;
}

// Driver program to test above function
int main() {
    int arr[] = {2, 3, 4, 10, 40};
    int x = 10;
    int n = sizeof(arr) / sizeof(arr[0]);
    int result = binarySearch(arr, 0, n - 1, x);
    (result == -1) ? printf("Element is not present in array")
                   : printf("Element is present at index %d", result);
    return 0;
}
```

It searches for a given number in a sorted array and returns the index of the number if found, otherwise it returns -1. The binary search algorithm is recursive and compares the given number with the middle element of the array, then recursively searches the appropriate half of the array.

Node* createNode(int data) {
    Node* newNode = (Node*)malloc(sizeof(Node));
    newNode->data = data;
    newNode->next = NULL;
    return newNode;
}

void insertAtHead(Node** head, int data) {
    Node* newNode = createNode(data);
    newNode->next = *head;
    *head = newNode;

void insertAtTail(Node** head, int data) {
    Node* newNode = createNode(data);
    if (*head == NULL) {
        *head = newNode;
        return;
    }
    Node* current = *head;
    while (current->next != NULL) {
        current = current->next;
    }
    current->next = newNode;
}

Node* findNode(Node* head, int data) {
    Node* current = head;
    while (current != NULL && current->data != data) {
        current = current->next;
    }
    return current;
}

void deleteNode(Node** head, int data) {
    if (*head == NULL) {
        return;
    }
    if ((*head)->data == data) {
        Node* temp = *head;
        *head = (*head)->next;

        return;

    Node* current = *head;

    current->next = current->next->next;

  intents=['definition'] topic='Quick Sort' best_distance=0.34599998593330383 (72s)
## QUICK SORT

📘 The time complexity of Quick Sort is O(n log n) in all cases. This algorithm works by partitioning the array into two halves, recursively sorting each half, and then merging them to get the original array sorted. The number of key comparisons is very close to the theoretical minimum, making it efficient. However, it has a significant extra storage requirement due to the use of an auxiliary stack.

💡 Think of Quick Sort as a fast assembly line that divides the work into smaller tasks (sorting halves), each of which is then handled by a worker (recursive calls). The time it takes to sort the entire line (array) is proportional to the number of tasks multiplied by the average time taken to complete each task (log n), resulting in a total time of O(n log n).
